# Cross-platform readiness audit checklist

Use with an authorized audit or affected feature review, alongside [cross-platform standards](cross-platform.md) and [testing/workflow](testing-and-workflow.md). This checklist extends future assessment instructions; it does not reopen or alter a prior baseline report. No audit, remediation, new issue, migration, live test or infrastructure work is authorized by its existence.

Record exact baseline, target clients/browser versions/input methods, inspected components and limits. For each item record standard ID, current/future applicability, Compliant / Partially Compliant / Noncompliant / Not Verified / Not Applicable, evidence, actual verification environment, impact and next-scope gate. Distinguish implemented, partial, planned and unverified capability. Never call untested behavior compliant.

| Assessment                        | Rules   | Evidence to collect                                                                                                                                                                                                 |
| --------------------------------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Responsive layout                 | X41     | Approved widths, portrait/landscape, long content, navigation, tables, dialogs, pinned controls, text/zoom, soft keyboard and unintended overflow.                                                                  |
| Browser compatibility             | X42     | Approved browser/OS/version policy, actual engine coverage, feature detection/fallback and unsupported capabilities. Surface an absent policy without inventing one.                                                |
| Input and accessibility           | X43/X44 | Keyboard/focus, touch, semantic structure, screen-reader/form/status behavior, contrast/branding, zoom/reflow and reduced motion; separate automated/manual/physical evidence and target from verified conformance. |
| Authoritative business operations | X45/X46 | Actual client/backend contracts, validation, tenant/permission/entitlement denial, version compatibility, errors and retry semantics. No UI or device trust as authority.                                           |
| Adaptive performance              | X47     | Actual payload/request/render/asset measurements and network method; pagination/loading/error states. Distinguish measured defects from scaling hypotheses.                                                         |
| Platform boundaries               | X48     | Existing platform-specific consumers, denied/unavailable/cancelled capability behavior and justified interfaces; no speculative adapters.                                                                           |
| Storage and session security      | X49/X50 | Actual SDK/persistence/cookie/cache handling, account/tenant switch, logout/back navigation, expiration/rotation/revocation, sleep/resume and private-token exposure. Mock Auth is not real token evidence.         |
| PWA readiness                     | X51     | Actual manifest/registration/install/update/cache/standalone behavior if present. If absent, assess reasonable boundaries only; optional functionality is not a current compliance defect.                          |
| Offline/synchronization           | X52     | Only approved operations: secure partitioned storage, conflicts/reconnect, current authority, duplicate delivery and reconciliation. Otherwise Not Applicable for implementation.                                   |
| Native readiness/distribution     | X53/X55 | Shared backend contract suitability and browser coupling; actual native lifecycle/auth/store obligations only when scoped. Record current dated platform policy sources if distribution is pursued.                 |
| Regression and device failures    | X54     | Exact executed responsive/browser/input/accessibility/auth/core-flow/network checks; emulation versus physical devices; unavailable checks and owner acceptance of material limits.                                 |

Classify actionable findings using the authorized audit's evidence and severity rules. Do not inflate severity because a future capability is missing. Preserve applied migration history, simulated payments, protected authorization boundaries and release restrictions. Any unsafe or state-changing validation needs its own approved scope; inspect test imports before execution, including helpers that initialize SQL migrations. No comprehensive audit or remediation issues are created by this documentation update.
