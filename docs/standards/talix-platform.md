# Talix platform rules

Classification and exceptions: [standards index](README.md). These constraints formalize direction without implementing an industry architecture or entitlement system.

| ID / level | Rule, purpose and applicability                                                                                                                                                                                                                                                       | Enforcement                                                                                                                                                                                                 |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P01 L1     | Shared core must remain independent of industry-specific modules. Industry extensions consume approved core contracts; core must not import an industry implementation or gain business-type special cases without an approved requirement/decision.                                  | Dependency and behavior review; core regression tests when an extension is introduced. No plugin loader is required today.                                                                                  |
| P02 L2     | Industry modules own their specialized rules and data. Restaurant, retail and future industries must not unnecessarily alter shared behavior. Explicit contracts define responsibility, ownership and compatibility at actual extension boundaries.                                   | Module/contract documentation and isolation tests when modules exist. Labels and demo catalogs do not demonstrate a module.                                                                                 |
| P03 L1     | When a subscription-restricted feature is introduced, centrally enforce its entitlement at every authoritative entry point, including background operations where applicable. UI visibility is derived guidance, never the security gate.                                             | Server/database denial tests for unentitled, changed/revoked and cross-tenant access; reviewed source of entitlement truth. No entitlement engine exists currently and none is authorized by this document. |
| P04 L2     | Support industry/tier evolution through explicit capability contracts rather than scattered plan-name checks. Examples such as Talix Basic, Restaurant and Restaurant Pro express future flexibility, not implemented offerings or entitlement promises.                              | Approved capability/plan mapping and backward-compatibility review when implemented. Current named tiers are Starter, Plus, Pro and Ultimate; inspect actual catalog for current terms.                     |
| P05 L1     | Preserve explicit client, subscription and location boundaries and existing permission enforcement. Additional subscriptions retain their own immutable purchase history and do not overwrite shared client details. Current industry changes use checked Owner transactions/history. | Tenant, purchase-preservation, authority and retry regressions.                                                                                                                                             |
| P06 L2     | Support both existing-website storefront links and a Talix primary-website path. Prefer constrained templates, branding/layout settings and supported configuration over per-business code forks.                                                                                     | Review approved design/schema and fallback behavior; do not claim embedded integration, full site building or custom domains already exist.                                                                 |
| P07 L1     | Preserve the owner's website direction: adjustable default templates should avoid an immediate extra recurring charge; custom website work may carry a custom design fee. Do not silently turn the website path into a recurring add-on or charge a fee.                              | Product/quote/onboarding review. Included limits, fee amount/basis, domains, hosting and support need a concrete approved proposal; no real billing activation.                                             |
| P08 L2     | New industries/features/tiers integrate through stable documented interfaces justified by current approved needs. Do not add speculative event buses, module registries, entitlement tables or frameworks in anticipation.                                                            | Boundary design and consumer evidence in PR/ADR.                                                                                                                                                            |
| P09 L1     | New features must preserve the approved core, storefront and existing applicable industry behavior. Assess compatibility and verify affected consumers before merge.                                                                                                                  | Risk-based automated tests and actual review evidence; specialized industry workflows remain unimplemented.                                                                                                 |
